# Автопостинг у Threads

Щодня о **9:00** і **19:00** (за польським часом) програма сама бере випадковий текст із твого Word-файлу і випадковий скріншот і публікує їх у Threads. Комп'ютер і телефон для цього не потрібні: все працює на серверах GitHub безкоштовно.

- Тексти й скріншоти не повторюються, поки не будуть використані всі. Потім починається нове коло в іншому порядку.
- Якщо текст довший за 500 символів (ліміт Threads), перша частина йде з картинкою, а решта автоматично публікується відповіддю під постом.
- Токен доступу до Threads продовжується автоматично раз на тиждень.

---

## Налаштування (один раз, ~30 хвилин)

### Крок 1. Створи репозиторій на GitHub

1. Зареєструйся на [github.com](https://github.com) (якщо ще немає акаунта).
2. Натисни **+** вгорі праворуч → **New repository**.
3. Назва, наприклад, `threads-autopost`. Обери **Public** і натисни **Create repository**.

> Чому Public: Threads приймає картинку лише за публічним посиланням, тому скріншоти мають бути доступні з інтернету. Тексти в Word-файлі теж будуть видимі, але вони однаково потрапляють у Threads. Секретний токен у публічний доступ **не** потрапляє (він зберігається окремо в «Secrets»).

### Крок 2. Завантаж файли

1. Розпакуй архів `threads-autopost.zip`.
2. У своєму репозиторії натисни **uploading an existing file** (або **Add file → Upload files**).
3. Перетягни **весь вміст** розпакованої папки, включно з папкою `.github`, і натисни **Commit changes**.

> На Mac папка `.github` прихована. Щоб її побачити у Finder, натисни **Cmd + Shift + .** (крапка). На Windows вона видима.
> Переконайся, що в репозиторії з'явилася папка `.github/workflows` з двома файлами. Без неї нічого не запуститься.

### Крок 3. Додай свої тексти й скріншоти

- **Тексти:** зайди в папку `posts` → **Add file → Upload files** → завантаж свій Word-файл (`.docx`). Назва будь-яка.
  - Пости у файлі розділяй **порожнім рядком**.
  - Якщо в одному пості є кілька абзаців, розділяй пости рядком із трьох дефісів `---`, тоді порожні рядки всередині поста збережуться.
- **Скріншоти:** зайди в папку `screenshots` → **Add file → Upload files** → перетягни всі картинки. Формат JPG або PNG, до 8 МБ кожна. Можна завантажувати частинами.

Видали файли-заглушки `posts/.gitkeep` і `screenshots/.gitkeep` не обов'язково, вони не заважають.

### Крок 4. Отримай доступ до Threads API

1. Зайди на [developers.facebook.com](https://developers.facebook.com) і увійди своїм акаунтом Facebook/Instagram (тим, до якого прив'язаний Threads).
2. **My Apps → Create App**. Введи назву, на кроці вибору сценарію (Use case) обери **Access the Threads API**. Заверши створення.
3. У застосунку відкрий **Use cases → Access the Threads API → Customize** і переконайся, що увімкнені дозволи **threads_basic** і **threads_content_publish**.
4. Відкрий **App roles → Roles → Add people → Threads Tester** і впиши свій нікнейм у Threads.
5. Прийми запрошення в Threads: **Налаштування → Акаунт → Дозволи для сайтів → Запрошення** (Settings → Account → Website permissions → Invites) → **Прийняти**.
6. Отримай токен: у розділі **Use cases → Access the Threads API → Settings** знайди **User Token Generator** і згенеруй токен для свого акаунта. Скопіюй його.
   - Якщо генератора там немає: відкрий [Graph API Explorer](https://developers.facebook.com/tools/explorer/), перемкни адресу з `graph.facebook.com` на `graph.threads.net`, обери свій застосунок і натисни **Generate Threads Access Token**. Це короткий токен на 1 годину, тож обміняй його на 60-денний, відкривши в браузері посилання (підстав свої значення; App secret є в **App settings → Basic** у розділі Threads):
     ```
     https://graph.threads.net/access_token?grant_type=th_exchange_token&client_secret=APP_SECRET&access_token=КОРОТКИЙ_ТОКЕН
     ```
     У відповіді скопіюй значення `access_token`.

### Крок 5. Збережи токени в GitHub

**5.1. Токен Threads**

У своєму репозиторії: **Settings → Secrets and variables → Actions → New repository secret**
- Name: `THREADS_TOKEN`
- Secret: токен із кроку 4
- **Add secret**

**5.2. Ключ GitHub для автопродовження токена**

Токен Threads живе 60 днів. Щоб програма сама його продовжувала, потрібен ключ GitHub:

1. Натисни на свою аватарку → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Назва будь-яка, термін дії максимальний (до 1 року).
3. **Repository access → Only select repositories** → обери свій `threads-autopost`.
4. **Permissions → Repository permissions → Secrets → Read and write**.
5. **Generate token** і скопіюй його.
6. Додай у репозиторій ще один секрет (як у 5.1): Name `GH_PAT`, Secret — цей ключ.

> Раз на рік цей ключ треба буде перевипустити й оновити секрет `GH_PAT`. GitHub надішле лист перед закінченням терміну.

### Крок 6. Перевірка

1. У репозиторії відкрий вкладку **Actions**. Якщо GitHub просить дозволу, натисни **I understand my workflows, go ahead and enable them**.
2. Ліворуч обери **Автопостинг у Threads → Run workflow**, постав галочку **«Опублікувати пост прямо зараз (тест)»** → **Run workflow**.
3. За хвилину-дві пост з'явиться у твоєму Threads. Зелена галочка означає успіх, червоний хрестик означає помилку: натисни на запуск, щоб побачити текст помилки.
4. Так само один раз запусти **Оновлення токена Threads**, щоб перевірити автопродовження. (Цей запуск спрацює, коли токену буде щонайменше добу.)

Готово. Далі все працює саме.

## Щоденне використання

- **Додати нові пости:** заміни Word-файл у папці `posts` (або додай ще один `.docx`, читаються всі).
- **Додати скріншоти:** просто завантаж нові картинки в `screenshots`.
- **Змінити час публікацій:** у файлі `autopost.py` зміни `MORNING_HOUR = 9` і `EVENING_HOUR = 19`. Якщо переносиш час суттєво, напиши мені, підлаштую і розклад запусків.
- **Поставити на паузу:** **Actions → Автопостинг у Threads → «···» → Disable workflow**.
- **Що вже опубліковано:** у файлі `state.json` (з'являється після першої публікації).

> GitHub може запускати процес із затримкою до 15–40 хвилин у години пікового навантаження, тож пост вийде приблизно о 9:00–9:40 і 19:00–19:40.
